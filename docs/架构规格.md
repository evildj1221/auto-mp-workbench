## 1. 产品定义

### 1.1 一句话

面向情感/治愈/成长类文字创作者的**开源、本地优先**内容生产平台：从全网风格蒸馏、
选题生成、写稿、质量门禁、排版、配图到公众号发布与数据复盘的**全链路工作台**，
以**对话式中控台**为主要交互形态。

### 1.2 用户

| 用户 | 场景 |
|---|---|
| 个人创作者（主用户） | 日常内容生产：对话下指令 → 拍板 → 出稿 → 发布 |
| 二次开发者 | 基于插件 ABI 扩展采集源/生成器/评分器/发布通道 |

### 1.3 核心工作流（平台的心跳）

```
采集(可选) → 风格蒸馏 → 选题生成 → [人工关卡①选题] → 写稿 → 标题
→ 质量门禁 → 排版 → 配图 → [人工关卡②发布] → 公众号草稿箱
→ 数据复盘 → 偏好学习(带探索配额) ─┐
└────────────── 回流选题生成 ←──────┘
```

### 1.4 双交互模式（缺一不可）

- **对话中控台（chat-first）**：主入口。用户与"编辑部"拟人角色对话下指令；
  关键决策以**卡片**内嵌对话流完成（确认卡/Top5 点选/标题点选/发布检查单）。
- **手动工作台**：精细控制面板（选题批次对比、长文编辑、校验报告、数据表格）。
  两模式读写同一数据源；任一入口的操作在另一入口实时可见。

### 1.5 v1 非目标（明确不做）

- 托管多租户/SaaS（架构预留，不实现）
- 内置对封闭平台（微信/小红书等）的爬虫
- 移动端
- 团队协作/多人权限

## 2. 账号档案系统（Profile）——平台的灵魂机制

**一切账号相关的表达必须档案化；代码零品牌。** 平台自身不预设任何调性。

### 2.1 Profile = 可移植文件包

```
profiles/
  <account-id>/
    profile.yaml        # 身份与配置（见 2.2 schema）
    style-dna.yaml      # 风格 DNA（表达层+世界观层，见 M1）
    redlines.yaml       # 内容红线（规则+级别）
    prompts/            # 提示词模板（带版本，见 §7.4）
    assets/             # IP 形象图、logo、参考图库
    themes/             # 排版主题与 UI 主题偏好
```

Profile **必须**可整体 zip 导出/导入（创作者之间分享风格的载体）。

### 2.2 profile.yaml schema（核心字段）

```yaml
id: slowpost            # 唯一 id
display_name: 你的公众号
niche: 情感/治愈            # 垂直领域
identity:                  # 人设（对话角色与文稿口吻的根源）
  voice: [温柔, 慢, 陪伴, 真实]
  persona_roles:           # 对话中控台的编辑团队（角色/花名/职责/主题色）
    - {id: chief,  name: 主编, duty: 统筹, color: "#e0a03c"}
    - {id: writer, name: 撰稿人, duty: 撰稿, color: "#4caf88"}
  ip_elements:             # IP 锚点（如：小猫·红项圈·木牌）
signature:                 # 固定签名结构（如收尾文案的逐字文本）
models:                    # 模型注册表绑定（按任务，见 §7.2）
  planner: {provider: deepseek, model: deepseek-chat}
  scorer:  {provider: deepseek, model: deepseek-chat}
  cover:   {provider: minimax, model: image-01}
budget: {max_steps: 40, max_cost_cny: 2.0}
gates:                     # 人工关卡配置（开启/跳过条件）
publishing: {wechat: {...}, archive: {...}}
```

**规则**：
- 平台**必须**内置一个**虚构示例 profile**（如"晚风信箱"），开箱即用；
- 真实账号（如创作工作台）的 profile 属用户私有，**永不入库**（见 §11）。

## 3. 核心域模型

### 3.1 领域概念（domain 层的全部名词）

| 概念 | 含义 | 关键属性 |
|---|---|---|
| Corpus | 采集/导入的语料 | 来源、账号、标题、摘要、全文(可空)、热度信号 |
| StyleDNA | 蒸馏出的风格分布 | 句式家族×占比、题材坐标覆盖、情绪曲线库、回避清单 |
| TopicCandidate | 选题候选 | 文本、系列、句式家族、题材坐标、五维分、新颖度分 |
| TopicBatch | 一批候选 | 轮次号、来源(生成/蒸馏) |
| Top5 | 批次前五 | 排名、总分、合规标记 |
| Selection | 选题决策 | 用户选择、备注、活动槽位 |
| Slot | 文稿槽位 | id **永不复用** `[H1-02]`、状态(draft/published) |
| Draft | 文稿版本 | v1/v2、字数、标记语法文稿 |
| TitlePlan | 标题方案 | 候选列表、已选标题、钩子类型 |
| GateResult | 门禁结果 | 红线/字数/相似度/语义 各分项 |
| TypoTheme | 排版主题 | 令牌(色/字号/间距)、组件开关 |
| Export | 排版导出 | html、校验报告、历史版本(封顶10) `[H1-24]` |
| Cover | 头图 | 路径、prompt、参考图标记 |
| PublishRecord | 发布登记 | 检查单、media_id、推送日志 |
| ReviewData | 复盘数据 | 阅读/在看/分享/涨粉 |
| ChatMessage | 对话消息 | 角色/角色id/卡片/事件标记 |
| ChatAction | 对话动作状态机 | offer→running→done，**先落盘后响应** `[H1-01]` |
| AgentRun | 应用 Agent 运行 | 状态、步数、成本、checkpoint |

### 3.2 选题坐标系（世界观的结构化）

每个选题/文稿**必须**可映射到坐标系上的一点：
- **情绪切口**：孤独、遗憾、和解、自我接纳、放下、想念、勇气…（profile 可扩展）
- **关系向度**：我-我 / 我-身体 / 我-你 / 我-他们 / 我-过去 / 我-世界
- **场景库**：深夜厨房、通勤、故乡、教室、阳台…（从语料与 profile 累积）

坐标系是多样性漏斗（M2）与差异报告（M1）的度量基础。

## 4. 功能规格（模块 M1–M10）

> 每模块给出：职责 / 关键规则 / 验收要点。实现顺序与里程碑见 §13。

### M1 采集与蒸馏

**职责**：把外部内容变成 StyleDNA 与选题灵感，不直接变成文稿。

**采集器 ABI（插件点 ①）**：
```
Collector.pull(niche, since) -> list[CorpusItem]
```
内置四个合规采集器：
1. `search-titles`：搜索 API 拉「领域+高阅读」标题+摘要（付费 API，key 由用户配）
2. `hotlists`：公开热榜聚合（情绪热点信号）
3. `rss`：用户自填 RSS 源（全文）
4. `llm-interview`：LLM 风格访谈（冷启动，零采集成本；产出**必须**经真实标题交叉验证）

**禁止**内置封闭平台爬虫；付费数据商（如新榜）做成**外置可选连接器**。

**蒸馏管线**：
```
corpus → 表达层特征(句式家族聚类/开头钩子/结尾/金句密度/句长分布/人称)
       → 世界观特征(题材坐标分布/选题来源模式占比/情绪曲线/回避清单)
       → style-dna.yaml
```
**必须**支持对自身历史文稿跑同一管线 → **差异报告**（哪些句式从没用过/过度使用/缺哪块象限）。

**验收**：对 ≥2 个不同 niche 各跑一次蒸馏，产出的 DNA 可被 M2 直接消费；差异报告
能量化（句式家族熵、象限覆盖率）。

### M2 选题引擎（含多样性漏斗——治"同质化"的核心）

**职责**：生成候选批次 → 评分 → Top5，**输出分布必须比输入 DNA 更宽**。

**多样性漏斗（必须全部实现）**：
1. **配额采样生成**：每批候选强制覆盖 ≥4 个不同句式家族、≥3 个题材象限；
2. **新颖度评分**：候选与「最近 N 篇已发 + 同批候选」的相似度惩罚（MMR）；
3. **Top5 配额**：入选的 5 条**必须**跨 ≥3 个句式家族（按总分排满则从被挤出的
   家族里回补最高分），禁止五条同构；
4. **ε-greedy 偏好学习**：学习用户偏好时**永远保留 20% 探索配额**——被用户排除的
   家族降权但不清零。

**继承规则**：L1 硬淘汰黑名单（句式/开场/致意类模板回避）来自 profile.redlines 与
DNA 回避清单 `[H2-2]`。

**验收**：连续生成 10 批，句式家族熵不下降；人为构造偏好后探索配额仍出非偏好家族。

### M3 写稿引擎

**职责**：标记语法文稿生成（v1/v2）、大纲、标题方案、改稿。
- 全部 LLM 交互走**结构化输出**（§7.3）；
- 标题方案：每条附钩子类型与理由；点选即定 `[H1-13]` 幂等；
- 写稿产物**必须**落活动槽位（槽位对齐规则 `[H1-14]`）。

### M4 质量门禁

**职责**：发布前的确定性+LLM 双层检查，输出 GateResult。
- 确定性层：红线短语（16 类×4 级 `[H2-1]`）、字数 900–1300（标准 900–1200 `[H2-3]`）、
  与近 4 天文稿相似句（阈值 0.45 `[H2-3]`）；
- LLM 层：语义红线（捕捉同义改写），失败降级不阻断；
- 门禁结果**必须**结构化落库并在 UI 可解释（哪条/为什么/建议动作）。

### M5 排版引擎

**职责**：标记语法 → 全内联 HTML + 确定性校验（20 项 `[H2-4]`）。
- 组件注册表制（scaffold 9 件 + 块级 11+ 件 `[H2-5]`），主题令牌化
  （色/字号/间距/圆角/字距），`:::marker` 围栏语法；
- **禁止** class/`<style>`/`<div>` 进产物；色值/字号白名单由生效主题派生；
- 导出历史封顶 10 版自动清理 `[H1-24]`；
- 产物中的本地图片引用**必须**可被预览层改写为可访问 URL `[H1-15]`。

### M6 配图引擎

**职责**：头图生成（v3 视觉系统全部规则 `[H2-6]`）。
- 系列口诀定调性 → 19 模板选型 → 景别轮换 → 六要素句式 → 参考图注入；
- 规格公账号封面 2.35:1（2048×872）；风格参考库按调性同池抽取；
- **禁止**：图内可读文字（一律虚化抽象墨痕 `[H1-04]`）、提示词出现
  Color palette/hex/百分比/accent `[H1-05]`；
- 未配 key / 生成失败**必须**优雅降级（不阻断导出，报告注明）。

### M7 发布通道（插件点 ④）

**职责**：公众号草稿箱推送 + 归档（飞书类）。
- 微信推送两步换装 `[H2-7]`：正文本地图片→微信 URL；头图→正文 URL+永久素材
  thumb（封面）；重推**必须**删旧草稿再建新（单篇）；
- 推送前**必须**校验出口 IP 白名单状态并给出明确提示（IP 卡：当前 IP/是否在单/
  一键复制）；
- 归档通道做成可选插件。

### M8 复盘与学习

**职责**：发布数据回流 → 偏好校准（ε-greedy，与 M2 共享机制）。
- 真实数据校准与自评学习**禁止**双写同一档案——**真实数据是唯一权威**；
- 复盘提醒：发布+3 天未录数据 → 中控台/概要提醒。

### M9 对话中控台（chat-first UI 的后端语义）

**职责**：拟人编辑部 + 卡片化决策 + 全工作台事件流。
- **路由**：关键词优先（零成本）→ LLM 意图兜底；@角色点名最高优先；
- **动作状态机**：offer→running→done；**先落盘后响应** `[H1-01]`；确认路径
  **锁内读-验-执行** `[H1-12]`；肯定/否定跟进直接执行/取消，不二次询问 `[H1-16]`；
- **动作单飞**：同目标重活按 key 互斥 `[H1-09]`；
- **卡片分类**：confirm / top5 / titles / checklist / next-step / 产物卡；
  卡片操作**必须**幂等（msg_id）`[H1-13]`；处理后盖"印章"；
- **事件流（方案 B 语义）**：任何入口（手动面板/CLI/Agent）的关键操作**必须**
  冒泡进当日对话流留痕（零 LLM 成本模板文案）；空闲 12s / 运行 2.5s / 发送中暂停
  的轮询纪律 `[H1-21]`；
- **组件化 DIY**：右侧面板全部独立组件（自订阅数据源、增删、拖拽调宽高、布局
  持久化、恢复默认）；中间对话框**不可删除**。

### M10 应用 Agent（自动化档位）

**职责**：给目标跑全链路，两道人工关卡（选题/发布），checkpoint 可续跑。
- 状态机：idle→planning⇄acting→waiting_topic/publish→paused_budget→done /
  interrupted / cancelled / error；
- **预算护栏**：成本按**当日真实 LLM 流水**（含工具侧）计 `[H1-10]`；
- **续跑不清零**：步数/成本从 checkpoint 播种 `[H1-11]`；
- **重启自愈**：内存任务丢失后持久状态判中断并可恢复，**禁止**永久卡死 `[H1-06]`；
- 关卡载荷可序列化（Top5 卡可直接在对话流/组件里点选）；
- 内核**框架无关**：编排框架（若用）只能是适配器依赖。

## 5. 架构规格

### 5.1 分层铁律（import-linter 机器强制）

```
contracts/            ← 单一事实源（OpenAPI + JSON Schema）
backend/
  domain/             ← 纯业务规则。禁止 import 任何 IO/框架
  application/        ← 用例编排。可 import domain
  infrastructure/     ← sqlite/llm/wechat/image/collector 适配器。可 import domain
  interface/          ← FastAPI 路由 + SSE。可 import application
frontend/             ← 从 contracts 生成 TS client；禁止手写 API 类型
agents/  plugins/  specs/  evals/  AGENTS.md
```

依赖方向**单向**；跨层直穿（interface→infrastructure 等）CI 直接红。

### 5.2 契约先行

- `contracts/openapi.yaml` 是 API 唯一事实源；后端路由模型、前端 client、
  契约测试全部由它生成或对它校验；
- 数据 schema（JSON Schema）同理，供 SQLite 迁移与 Profile/导出文件共用；
- 契约变更必须走 PR + 版本号（major.minor），前端后端并行开发不联调爆炸。

### 5.3 Agent 原生仓库（给多 agent 并行开发的机制）

| 机制 | 规格 |
|---|---|
| `AGENTS.md` | 仓库地图、命令（verify/lint/test）、DoD、代码规范、提交规范；机器可读优先 |
| `specs/` | 每模块 spec.md + 契约引用 + 验收清单；实现 agent 只读该模块 spec 即可开工 |
| 文件纪律 | 一文件一概念；公开 API 只经 `__init__.py`；禁止上帝文件（>400 行需拆分理由） |
| `make verify` | 一条命令：lint + 类型 + 单测 + 契约测试 + 冒烟；agent 交付前必须自跑 |
| CI 门禁 | verify 全绿 + import-linter + gitleaks + 格式检查；Conventional Commits |
| `evals/` | 黄金集回归：换模型/改提示词必须跑分且不退化才可合入 |

### 5.4 插件 ABI（pip entry-points，四个扩展点）

```
平台插件点 = collector（采集） | generator（生成） | scorer（评分） | publisher（发布）
每个点定义最小接口 + 注册装饰器 + 独立目录示例插件
```
插件**必须**可用 `pip install` 独立分发，核心零改动加载。

## 6. 数据规格

### 6.1 存储

- SQLite（WAL）+ SQLAlchemy 2 + Alembic 迁移；**禁止** json 文件当数据库；
- **追加式事件表** `events`：所有领域事件（决策/审批/生成/发布…）append-only，
  取代散落日志文件，支撑审计与对话事件流；
- 写入**必须**事务化；JSON 字段用 tmp+replace 语义不适用（DB 已解决 `[H1-08]` 的
  文件版问题，但导出的独立 json 文件仍按 `[H1-08]` 原子写）。

### 6.2 核心表（schema 骨架，Alembic 生成细节）

corpus_items / style_dnas / topic_batches / topic_candidates / top5 /
selections / slots / drafts / title_plans / gate_results / typo_themes /
covers / exports(含历史指针) / publish_records / review_data / chat_messages /
chat_actions / agent_runs / llm_calls(成本账本) / events / settings

### 6.3 用户数据目录（永不入仓）

```
~/.<app>/
  app.db            # SQLite
  profiles/         # 用户 profile 包（含真实账号）
  corpus/           # 语料缓存
  media/            # 图片产物
  themes/           # UI 主题文件
  logs/
```

### 6.4 旧数据迁移

创作工作台私有数据由一次性导入工具完成（映射表见 `[H3]`）：旧 json/文件 → 新 schema +
私有 profile 包。导入工具在**旧仓维护**，新仓只提供标准导入接口。

## 7. AI 能力层规格

### 7.1 Provider 适配器

统一接口 `generate / analyze / structured / embed`；实现：OpenAI 兼容（DeepSeek/
Ark/…）、Anthropic、MiniMax(文生图)、即梦/Seedream。**禁止**业务层直接 import 具体
provider SDK——只经适配器。

### 7.2 模型注册表

按任务绑定（planner/writer/scorer/judge/cover/…），**按 profile 可覆盖**；
换模型 = 改配置 + 跑 evals，零代码改动。

### 7.3 结构化输出

所有 LLM 调用**必须**声明输出 JSON Schema；解析失败重试 ≤3 次后走错误信封，
**禁止**裸文本解析进业务。

### 7.4 提示词资产化

提示词是版本化资产：`prompts/` 内带 id/version/变体；每次变更关联 eval 得分；
profile 可覆盖任意提示词槽位。

### 7.5 Eval 体系

- 黄金集：从 profile 语料 + DNA 构造（选题质量/标题合规/文稿结构/红线召回）；
- 回归门禁：模型/提示词/评分器变更必须 evals 不退化；
- 成本可见：每次调用入 `llm_calls` 账本，UI 实时电表。

## 8. UI/UX 规格（前端）

### 8.1 技术与结构

React 19 + TypeScript strict + Vite + TanStack Query；feature-sliced 目录；
API client 从 contracts 生成；状态：服务端状态用 Query，本地 UI 状态用组件态，
**禁止**引入全局 store 除非出现跨页共享的客户端状态需求。

### 8.2 设计令牌 2.0

全部视觉量收进 CSS 变量（色/圆角/阴影/间距/字号/动效）；默认主题：
**纯白底 + 暖色点缀** + 暗色主题；**禁止**在组件写死颜色/字号。

### 8.3 图片驱动主题（核心差异化功能）

```
上传图片 → 调色板提取(k-means, 后端) → 角色映射(bg/surface/accent/ink/muted)
→ WCAG AA 对比度自动校验(不过自动调到过) → 用户微调 → 保存 .theme.json → 可分享
```
主题切换即时生效于全站（令牌层实现，零组件改动）。

### 8.4 布局 DIY（M9 前端形态）

组件注册表（时节/流水线/预览/台务/运行态/时间线/趋势/金句/链接…）；拖拽排序、
多列、拖拽调宽高、布局持久化(localStorage)、预设导入导出、恢复默认；组件独立
订阅数据源——**删了再加回即最新数据**（数据在服务端，组件只是视图）。

### 8.5 对话流规范

- IME：Enter 提交**必须**检查 isComposing/keyCode 229 `[H1-03]`；
- 卡片系统与印章态 `[H1-13]`；乐观气泡 + 发送中暂停轮询 `[H1-21]`；
- 智能滚底（用户在底部才跟随）；
- 所有 mutation 失败**必须** toast `[H1-17]`；fetch 全局超时 `[H1-15]`。

### 8.6 首启向导（开源第一印象）

5 步：选 niche → 调性/红线 → 传 logo/IP 图（顺带生成 UI 主题）→ 绑模型 key →
生成第一批判例选题。全程 ≤5 分钟出第一个可拍板的 Top5。

### 8.7 可访问性基线

对比度 ≥ WCAG AA（主题生成器强制）；图标按钮带 aria-label；命中区 ≥40px；
禁用态带 title 说明；焦点可见。
